# HPCMosaic — Codebase Overview

Orientation doc for anyone (human or AI) starting work on this repo. Read this first, then open only the files relevant to the task.
Last verified against commit `8eb3fe4` (after Drona Composer removal, PR #99).

---

## 1. What this is

**HPCMosaic** is a user-customizable dashboard for HPC cluster users at Texas A&M HPRC (clusters: ACES, Grace, FASTER, Launch…). Users drag widget "cards" onto a grid to see their jobs, quotas, project accounts, node status, and to submit support requests.

- **Runs as an Open OnDemand (OOD) Passenger app.** Each user gets their own process (a "PUN"), running **as that user**. The backend therefore identifies the user via `os.environ["USER"]` — there is no login/session layer.
- **URL base:** `/pun/dev/<APPNAME>` (dev sandbox) or `/pun/sys/<APPNAME>` (production). All API calls are `<base>/api/...`.
- **Stack:** Flask 2.0 backend (Python) + React 18 SPA bundled by Webpack, styled with Tailwind 3 + CSS variables. No database — state is JSON files on disk.
- Repo: `github.com/tamu-edu/dor-hprc-HPCMosaic`. Working branch is usually `hprc-dev`; `main` is the PR target.

## 2. Build, run, deploy

| Task | Command / action |
|---|---|
| First-time setup (on cluster, inside OOD dev/sys dir) | `./setup.sh` — prompts for cluster name, login node, dev/prod; generates `config.yml` + `manifest.yml` from `*.template` via `envsubst`; creates `var/announcements/announcements.json`; makes `.venv`; `pip install`; `npm run build` |
| Frontend rebuild | `npm run build` (prod) · `npm run build:development` · `npm run build-watch` |
| Backend change | Restart the PUN: OOD portal → Help → "Restart Web Server" (or `touch tmp/restart.txt`) |
| Local run | `python app.py` (needs `USER` env var and a `config.yml`; most endpoints shell out to Slurm/cluster tools and will fail off-cluster) |

- Webpack entry `src/index.js` → output **`static/bundle.js`** (gitignored). Flask serves `templates/index.html`, which is just `<div id="root">` + the bundle.
- **There is no test suite** for the main app. Verify changes by building and loading the dashboard on a cluster dev instance.
- `requirements.txt` pins old versions (Flask 2.0.3 etc.) for compatibility with cluster Python.

## 3. Configuration

- `config.yml` (generated, committed in current state) has `development:` (YAML anchor `&common_settings`) and `production:` (`<<: *common_settings` + overrides). Keys: `cluster_name`, `login_node`, `announcements_file`, `dashboard_url`, `file_app_url`, `file_editor_url`, `request_email`, `help_email`, `hprcbot_route`, `dashboard_fonts`.
- **Always edit `config.yml.template`** for structural changes; `config.yml` is regenerated by `setup.sh`.
- Config is read in **three different places**, with inconsistent section choice:
  - `app.py` → picks `development` or `production` via `detect_env()` (RACK_ENV, or `/dev/` vs `/sys/` in path) → `app.config` (used via `current_app.config[...]`, e.g. `login_node`, `cluster_name`).
  - `views/api/config.py` → module constants; **always reads the `development` section** (variable misleadingly named `_production`). Used by `bot_requests.py`.
  - Frontend imports `config.yml` directly via `yaml-loader` (`import config from "../../config.yml"`). Note yaml-loader keeps the merge key literally, so production values may live under `config.production['<<']` — see `src/composer/schemas/requestProfile.js` for the correct merge.

## 5. Frontend architecture

### Component tree
```
index.js
└─ SandboxGrid
   └─ Banner (framework/Banner.js)  ← the real app shell & state owner
      ├─ top bar: Refresh, "Add Element", Settings menu (LayoutUtility, theme, font size, font family), HelpButton
      ├─ LayoutLockProvider
      │  └─ Content (framework/Content.js) ← react-grid-layout, 12 cols, rowHeight 20, drop target
      │     └─ per item: CardConfig[name].chartComponent
      ├─ bottom drawer: Sidebar ← lists CardConfig entries as draggable Card tiles
      └─ lock-layout floating button
```

### The card registry — `src/framework/CardConfig.js`
Central map of **display name → config**. The key string *is* the card's identity (stored in saved layouts).
```js
"Card Name": {
  description, icon, category: "analytics" | "system" | "user",
  chartComponent: MyComponent,   // rendered inside the grid cell
  defaultW, defaultH, minW, minH, // grid units (12 cols wide; row = 20px)
  adminOnly: true,                // optional; only shown if /api/announcements says can_manage
}
```
`cardComponent` (the sidebar tile) is auto-generated from `Card.js`.

**To add a new card:** create component in `src/elements/`, add entry to `CardConfig`, optionally add to `DefaultLayout.js`, add backend route if needed. **Renaming a card key breaks saved layouts** — add an alias in `CARD_NAME_ALIASES` (Content.js) and/or `LEGACY_CARD_NAME_ALIASES` (dashboardLayoutPersistence.js).

### Layout state & persistence
- Layout = array of `{ name, i (uuid), x, y, w, h }`, owned by `Banner` (`layoutData`), mutated via `commitLayout` / `addDashboardItem` / `removeDashboardItem` / `commitGridLayout`.
- **Auto-saved current layout:** `dashboardLayoutPersistence.js` → `POST /api/save_preferences` key `dashboard_layout` (payload has `schemaVersion: 2`, `knownDefaultCardNames`), debounced 600 ms, only after the user actually edits. Falls back to `localStorage` `mosaic.dashboard_layout.v1`. On load, `mergeDashboardLayout` appends *newly introduced* default cards the user has never seen.
- **Named layouts:** `layoutUtils.js` ↔ `/api/save_layout|get_layouts|load_layout|delete_layout|rename_layout`. Stored at `~/.HPCMosaic/layouts/<name>.json` (format `{"0": [...]}`; base dir overridable via `$HPCMOSAIC_DATA_DIR`); preferences in `_preferences.json` in the same dir. On first access, files from the old `/scratch/user/$USER/ondemand/layouts/` are copied over (scratch copy left in place). Layout names are validated by `resolve_layout_path` in `utils.py`.
- `DefaultLayout.js` defines the first-run layout.

### Data fetching conventions
- Base URL: always `get_base_url()` from `src/utils/api_config.js` (derives `/pun/dev|sys/<app>` from `window.location`).
- Preferred pattern for read-only cards: `useApi("/api/…")` from `src/elements/dashboardUtils.js` → returns `{data, loading, error}`, uses `sharedGet` (dedupes concurrent identical GETs, 15 s cache) and re-fetches on the global refresh event.
- Global window events: `"mosaic-dashboard-refresh"` (Refresh button; cards should re-fetch with `refresh: true`), `"mosaic-dashboard-layout-modified"`.
- Older cards (`UserJobs`, `QuotaInfo`, `Accounts`, `ClusterInfo`, `PyVenvManager`…) use ad-hoc `fetch`/`axios` + `Spinner`.
- `dashboardUtils.js` also exports shared UI bits: `KpiCard`, `MiniNodeBar`, `cardClasses`, node-status colors/labels, number formatters.

### Styling / theming
- Tailwind (`tailwind.config.js`) with a `mosaic.*` color palette mapped to CSS variables `--mosaic-color-*`, set at runtime by `src/context/ThemeContext.js` (themes: light, dark, darkLavender, darkPink; card font scale `--mosaic-card-font-scale`; font family). User choice stored in `localStorage`.
- Use `theme-*` utility classes (`theme-surface`, `theme-text-primary`, `theme-border`, `theme-selected`…, defined in `src/style.css`) or `bg-mosaic-*`/`text-mosaic-*` — **avoid hard-coded colors** so all themes work. Text sizes inside cards use `text-card-NN` (scaled by font-size setting).
- Inside a grid cell, interactive elements need class **`non-draggable`** or clicks start a grid drag (`draggableCancel=".non-draggable"`).

## 6. Request forms (the "composer")

Support-request popups (quota, group, help, acknowledgement) are rendered from **JSON schemas**:
- `src/composer/PopupForm.js` → modal wrapper; `ComposerWrapper.js` → `<form>`, required-field validation (`RequiredFieldsModal`), submit gating; `schemaRendering/Composer.js` + `FieldRenderer.js` render fields.
- Field types (`schemaRendering/schemaElements/index.js` `componentsMap`): `text`, `textarea`, `select`, `radioGroup`, `unit`, `staticText`, `rowContainer`, `collapsibleRowContainer`, `collapsibleColContainer`. Containers nest via `elements`.
- `"condition": "fieldName.value"` shows/hides a field; supports `&&`, `||`, `!`, `^`, parentheses (`utils/conditionEvaluator.js`). Hidden fields aren't rendered, so they're excluded from validation and submission.
- **Per-cluster schemas:** `src/composer/schemas/requests/<profile>/<form>.json`, where profile = lower-cased `cluster_name`. `loadRequestSchema('quotaRequest.json')` falls back to `default/`. Existing overrides: `aces/`, `launch/`. Adding a new cluster variant = drop a JSON file in a new folder; no code change.
- This is a vendored, trimmed copy of the old Drona Composer renderer (Drona itself was removed in PR #99 — don't reintroduce the submodule).

## 7. Backend architecture (`views/api/`)

One Flask Blueprint `api` (in `__init__.py`), mounted at `/api`. Each module does `from . import api` and decorates routes; it must be imported in `__init__.py` to register. The `__init__.py` docstring is the maintained route index — update it when adding routes.

| Module | Responsibility | Talks to |
|---|---|---|
| `info.py` | `/user-data`, `/sinfo`, `/showquota`, `/groups`, `/nodes`, `/gpu-resources`, `/node/<n>`, `/node/<n>/jobs`, `/cpuavail`, `/system-load` | `sinfo`, `scontrol`, `squeue`, `/sw/local/bin/{retrieve_sinfo,showquota,cpuavail}`, `os.getloadavg()` |
| `jobs.py` | `/jobs`, `/jobs/past_jobs`, `/jobs/summary`, `/jobs/<id>`, `/cancel_job/<id>`, `/utilization` | `squeue`, `sacct`, `scontrol`, `scancel`, `/sw/local/bin/pestat` |
| `jobstats.py` | `/jobs/<id>/jobstats` — parses optional jobstats monitoring logs (ownership checked via `sacct`) | filesystem |
| `priority.py` | `/priority/queue-insight` — queue position / priority explanation | `sprio`, `squeue`, `scontrol` |
| `projects.py` | `/projectinfo`, `/set_default_account` | `/sw/local/bin/myproject` |
| `modules.py` | Venvs (`/get_env`, `/create_venv` via **SSH to `login_node`**, `/delete_env`, `/get_py_versions`) and module catalog (`/available_modules*` from `modules/<cluster>-modules.json`) | `ssh`, `/sw/local/bin/{create_venv,delete_venv,toolchains}`, `modulair` |
| `quota_inspection.py` + `quota_usage_scan.py` | `/quota/inspection` — pipes `quota_usage_scan.py` to `python3 -` over SSH on the login node; bounded scan (30 s / 250k entries), results cached 5 min; paths restricted to the user's `showquota` paths | `ssh`, `showquota` |
| `bot_requests.py` | `/quota`, `/group`, `/help`, `/software`, `/account`, `/submit_acknowledgement` — POST to HPRC Bot at `{hprcbot_route}/HPRCapp/OOD`; quota falls back to SMTP (`smtp.tamu.edu:25`) | HPRC Bot, SMTP |
| `announcement.py` | `/announcements` (public, returns `can_manage`), `/admin/announcements` CRUD + `/order`. File-locked, atomic writes, revision-based optimistic concurrency (409 on conflict), same-origin check. **Admin = has filesystem write access to the announcements file** (group `hprc`, set up by `setup.sh`) | `var/announcements/announcements.json` |
| `layout.py`, `preferences.py` | Named layouts and per-user prefs JSON under `~/.HPCMosaic/layouts/` (migrated from scratch on first access) | filesystem |

**Shared helpers:**
- `utils.py`: `run_process_output(argv_list, timeout)` (**preferred** — no shell), `run_command(str)` (shell=True, legacy), `get_user_email` (reads `/usr/local/etc/email_mapping.access.login`, falls back to `user@tamu.edu`), `get_group_directory_info`, `get_data_dir` / `get_layouts_dir` / `resolve_layout_path`, `safe_int/float`, `parse_storage_to_mib`, etc.
- `cache.py`: `TTLCache.get_or_set(key, ttl, loader)` — in-process cache with in-flight dedupe; used for Slurm queries (e.g. active jobs 10 s, summary 20 s, sacct 300 s, node snapshot 20 s).
- `slurm_jobs.py`: `scontrol show job -o` parser.

**Conventions:** return `jsonify(...)`, errors as `{"error": msg}` with a 4xx/5xx; validate any user-supplied value that reaches a command (e.g. `SAFE_NODE_NAME`, `_JOB_ID_RE`); use argv lists, not shell strings, for new commands.

## 8. Gotchas & known issues

- Everything depends on cluster tooling (`/sw/local/bin/*`, Slurm, SSH to login node, `/scratch`). Off-cluster, most endpoints 500 — that's expected.
- `login_node` empty in config ⇒ venv creation/listing and quota inspection are disabled with an error.
- `views/api/config.py` always uses the `development` section of `config.yml`.
- Some legacy endpoints build shell strings with request data (`projects.py` `myproject -p {account}`, `-d {account_no}`) — treat as injection-risky; sanitize or convert to argv if touching them.
- The static `CARD_NAME_ALIASES` / `LEGACY_CARD_NAME_ALIASES` exist because card keys were renamed ("Accounts Usage Summary" → "Accounts", old "Accounts" → "Project Information", "GPU Utilization" → "GPU Resources").
- `static/bundle.js` is a build artifact; never edit it. Legacy `static/` libraries and `templates/layout*.html` are leftovers from the Drona era.
- `__pycache__/` dirs are present but should not be committed.
- Frontend console logging is noisy (emoji logs in `layoutUtils.js`, form debug logs); fine to trim when touching those files.
